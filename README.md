# LocalPhotosSync: первый USB-прототип

Нативное приложение для macOS 14+ без сторонних зависимостей. На iPhone ничего устанавливать не нужно. Прототип использует системный ImageCaptureCore, как инструменты импорта с камеры.

## Запуск

Нужны Xcode или инструменты командной строки с поддержкой Swift 6.

```sh
zsh scripts/build-app.sh
open '.build/LocalPhotosSync USB.app'
```

Сборка сначала готовит и проверяет новый экземпляр приложения, затем заменяет текущую папку. Прежний экземпляр сохраняется в `.build/previous-apps/`: его исполняемые файлы не перезаписываются, поэтому запущенный процесс может закончить работу. Для использования новой версии перезапустите приложение после окончания переноса.

1. Подключите iPhone к Mac кабелем.
2. Разблокируйте его и подтвердите «Доверять этому компьютеру», если появится запрос.
3. Разрешите доступ на Mac, если система его запросит. На время проверки закройте другие программы импорта с телефона.
4. Дождитесь списка файлов и выберите несколько фото и короткое видео.
5. Нажмите «Сохранить выбранные…» и выберите папку вне iCloud Drive.
6. Откройте полученную папку и проверьте воспроизведение/просмотр файлов. В `import-report.json` записаны результаты импорта.
7. Нажмите «Проверить папку архива…» и выберите созданную папку. Эта проверка доступна и после отключения iPhone.

Каждый запуск импорта создаёт новую папку. Каждый выбранный файл сохраняется в отдельную подпапку, чтобы одинаковые имена и сопутствующие файлы не перезаписывали друг друга. Полученный файл читается целиком потоковым способом, сверяется его размер, рассчитывается SHA-256. Доступные сопутствующие файлы в той же подпапке также получают контрольные суммы. Это **не** сравнение контрольных сумм с исходником на iPhone.

Отчёт создаётся до первого копирования и остаётся незавершённым до обработки всей выборки. Кнопка «Отменить перенос» и отключение телефона оставляют незавершённый отчёт; частичный импорт не должен выглядеть готовым архивом. Полученные файлы сохраняются для проверки, а исходники на телефоне не меняются.

Повторная проверка обнаруживает отсутствующие файлы, изменение размера и контрольной суммы, ошибки и незавершённость импорта. Относительные пути позволяют переместить целиком папку архива и проверить её на новом месте. Старые отчёты без признака завершённости не считаются подтверждённо завершёнными.

Если подключение не работает, кнопка «Скопировать диагностику» копирует версию macOS и приложения, состояние подключения и числовые показатели. Серийные номера и имена фотографий в диагностику не включаются.

## Что проверяем

Первый эксперимент: обнаружение телефона, каталог доступных по USB файлов, миниатюры, выбор на Mac и сохранение выбранных файлов. Приложение не удаляет фотографии и не изменяет библиотеку iCloud.

USB-каталог не равен полной библиотеке PhotoKit: оригиналы только в iCloud, скрытые снимки и структура альбомов могут быть недоступны. Live Photo может показываться парой отдельных файлов; полнота его экспорта пока не подтверждается. При преобразовании форматов на стороне iPhone проверка размера может сообщить ошибку — её нельзя считать успешным архивированием.

На первом проверенном телефоне при включённой оптимизации iCloud USB предоставил 326 изображений и 6 видео, тогда как «Фото» на iPhone показывает 2 132 фото и 429 видео. Полный каталог этим способом не подтверждён. Следующая проверка — системная медиатека «Фото» на Mac, синхронизированная с тем же iCloud.

Для проверки оригинальных форматов можно выбрать на iPhone: Настройки → Приложения → Фото → Перенос на Mac или ПК → Сохранять оригиналы. Название и путь зависят от версии iOS.

Веб-приложение по Wi-Fi может принимать файлы, вручную выбранные пользователем на iPhone. Оно не получает через стандартный файловый выбор доступ ко всей медиатеке для просмотра на Mac и удаления снимков. Поэтому первым выбран эксперимент с USB. Wi-Fi через сопряжение с компьютером проверяется отдельно от полноты медиатеки.

## Проверки без управления окном

После сборки доступны команды:

```sh
'.build/LocalPhotosSync USB.app/Contents/MacOS/LocalPhotosSyncUSB' --diagnose --seconds 5
'.build/LocalPhotosSync USB.app/Contents/MacOS/LocalPhotosSyncUSB' --verify-archive '/путь/к/папке/архива'
python3 scripts/diagnose-environment.py --browse-seconds 5
```

`--diagnose` ждёт указанное число секунд и выводит состояние подключения и числовые показатели без имён устройств и файлов. `--verify-archive` проверяет сохранённую папку без подключения телефона: код выхода 0 означает успешную проверку, 1 — проблему с архивом, 2 — ошибку запуска или чтения отчёта. Обе команды возвращают JSON.

Python-скрипт отдельно считает USB-устройства iOS, объявления Bonjour и устройства, доступные системному usbmuxd. Он не создаёт сопряжение и не читает фотографии. Наличие объявления в сети ещё не подтверждает доступ к телефону; детали — в [описании Wi-Fi-пробы](docs/wifi-probe.md).

## Проверка каталога «Фото» на Mac

Это отдельная проба системной библиотеки Mac, а не прямое чтение телефона. Сначала проверьте в «Фото», что используется нужная системная медиатека, включён тот же iCloud и синхронизация завершена. Проба не меняет аккаунт или настройки синхронизации.

```sh
'.build/LocalPhotosSync USB.app/Contents/MacOS/LocalPhotosSyncUSB' --probe-mac-library
```

Без разрешения команда выводит его статус без счётчиков. Для первого системного запроса доступа:

```sh
'.build/LocalPhotosSync USB.app/Contents/MacOS/LocalPhotosSyncUSB' --probe-mac-library --request-access --seconds 60
```

Запускайте именно бинарник внутри собранного `.app`. macOS предлагает доступ уровня чтения и записи; код этой пробы только читает метаданные и не вызывает изменение библиотеки. При отказе разрешение нужно изменить вручную в настройках macOS — повторный флаг не обходит отказ.

JSON содержит источник `mac_system_photos_library`, статус доступа и количества фото, видео и прочих объектов. Имена, идентификаторы и содержимое файлов не читаются для вывода. Скрытые объекты исключены, серии учитываются представительными снимками. При отсутствии доступа, недоступности библиотеки или тайм-ауте счётчики равны `null`; это не пустая медиатека. Код выхода: 0 — каталог прочитан, 1 — проверка не удалась, 2 — неверные аргументы или ошибка формирования ответа.

Состояние iCloud и полнота библиотеки остаются `unknown`: сравните результат с числом объектов на iPhone и состоянием «Фото» на Mac. Проба не загружает оригиналы и не удаляет фотографии. Если каталог подтвердится, выбранные облачные оригиналы можно будет получать на Mac через интернет; такой экспорт пока не реализован. [Об ограничениях и эксперименте](docs/missing-media.md).

## Автоматический пробный импорт

Для воспроизводимой проверки с подключённым, разблокированным iPhone:

```sh
mkdir -p .build/device-probe
'.build/LocalPhotosSync USB.app/Contents/MacOS/LocalPhotosSyncUSB' --probe-import '.build/device-probe' --seconds 60
```

Эта команда **скачивает** одну самую маленькую доступную фотографию и, если есть подходящее видео, одно видео. Каждый основной файл должен иметь известный положительный размер до 32 МБ. Автоматическая загрузка сопутствующих файлов выключена только в этой пробе; обычный перенос из окна приложения сохраняет их по-прежнему. Поэтому проба не проверяет полноту Live Photo.

Требуются ровно одно доступное устройство и транспорт USB. Результат — JSON с путём новой папки, количеством выбранных фото и видео, байтами и результатом проверки. Код выхода 0 означает успешный импорт и проверку архива; 1 — ошибку или тайм-аут; 2 — неправильные аргументы. Если маленького видео нет, `selectedVideos` будет 0: перенос видео тогда не подтверждён. На тайм-ауте отчёт остаётся незавершённым. Исходники на телефоне не удаляются.

Первый реальный перенос фото и видео прошёл; подробности и оставшиеся проверки — в [результатах эксперимента](docs/device-test-results.md).

## Проверки кода

```sh
swift test
python3 -m unittest discover -s Tests/EnvironmentDiagnostics
```

Проверки покрывают контрольную сумму, усечённые и пустые файлы, незавершённые отчёты, повреждение и потерю файлов, перемещение архива и недопустимые пути. Чтение медиатеки и перенос требуют проверки на реальном iPhone.

Источники: [ImageCaptureCore](https://developer.apple.com/documentation/imagecapturecore), [USB-импорт Apple](https://support.apple.com/guide/image-capture/transfer-images-imgcp1003/mac), [файловый выбор в браузере](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/input/file), [Wi-Fi-сопряжение Finder](https://support.apple.com/en-gb/102471).

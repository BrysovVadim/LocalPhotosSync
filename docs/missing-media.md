# Проверка неполного каталога

Пользователь подтвердил, что отсутствуют сами карточки, а не только миниатюры. На iPhone включена оптимизация хранилища; приложение «Фото» показывает **2 132 фото и 429 видео**. Готовый USB-каталог прототипа содержит **326 изображений и 6 видео**. USB в текущей конфигурации не обеспечивает просмотр всей медиатеки. Успешный перенос двух файлов не доказывал полноту библиотеки.

Счётчики iPhone относятся к объектам медиатеки, а USB — к файлам: один объект может иметь несколько ресурсов. Поэтому разность этих чисел нельзя считать точным количеством пропущенных объектов.

## Уже проверено

- В интерфейсе нет ограничения количества карточек; действуют поиск и фильтр типа.
- Сборщик рекурсивно обходит папки и добавляет `camera.mediaFiles` при готовности каталога. Файлы удерживаются словарём, поэтому повторное использование адресов объектов не может перезаписать ещё удерживаемые файлы.
- Неудачная загрузка миниатюры оставляет карточку со значком. Она может объяснить пустые превью, но не исчезновение самих карточек. Повторной попытки для остающейся на экране карточки сейчас нет.
- USB-инвентарь видит телефон, но отдельные свежие CLI-запуски ImageCaptureCore получили 0 устройств. Это другой клиент; его нулевой результат нельзя приравнивать к содержимому уже работающего GUI.
- Контрольный экземпляр того же CLI с отдельным Bundle ID получил готовый каталог: `mediaFiles=332`, рекурсивный `contents=334`, `store.items=332`, готовность SDK 100%. Это поддерживает гипотезу взаимодействия контекстов клиентов, но не устанавливает её механизм. Два дополнительных SDK-объекта ещё нужно классифицировать; они не объясняют разницу масштаба всей медиатеки.

## Что измеряем

В диагностику добавлены процент готовности, число файлов в плоском `mediaFiles`, число файлов в рекурсивном `contents` и число объектов этих снимков, отсутствующих в `store.items`. Обход дерева защищён от повторного посещения объектов. Вывод содержит только счётчики.

Сравнивать нужно данные одного работающего окна. Счётчик отсутствующих объектов основан на `ObjectIdentifier`: расхождение ещё нужно проверить на предмет разных SDK-объектов, представляющих один физический файл.

Для актуальной диагностики:

1. Дождаться окончания переноса, если он идёт.
2. Закрыть приложение через ⌘Q и открыть `.build/LocalPhotosSync USB.app` заново, чтобы загрузилась новая сборка.
3. Выбрать «Все», очистить поиск, дождаться каталога.
4. Нажать «Скопировать диагностику» и передать текст.
5. Уточнить, отсутствуют ли карточки или только их изображения; сравнить с числом фото и видео в «Фото» на iPhone.

## Ограничения, которые проверяем отдельно

При оптимизации iCloud полноразмерные оригиналы могут храниться в облаке, а на телефоне — уменьшенные копии. Пользователь подтвердил эту настройку. Это существенное ограничение выбранного USB-подхода; соответствие каждого отсутствующего файла облачному оригиналу пока не установлено. Загружать всю библиотеку обратно на телефон с целью освобождения места не предлагается. [Apple об оптимизации хранилища](https://support.apple.com/en-us/105061).

Apple также указывает, что начиная с macOS 15.4 содержимое заблокированного альбома «Скрытые» не импортируется через Image Capture. Изменять защиту альбома без выяснения, какие файлы отсутствуют, не требуется. [Руководство Image Capture](https://support.apple.com/guide/image-capture/transfer-images-imgcp1003/mac).

## Следующий маленький эксперимент: только iPhone

Пользователь уточнил требование: источник — сам iPhone, медиатека «Фото» на Mac не подходит. Прежняя команда `--probe-mac-library` отключена; описание доступа и entitlement Mac Photos удалены из активной сборки. Исходник сохранён вне SwiftPM target в `experiments/mac-photos/`. Настраивать iCloud Фото или разрешать доступ к медиатеке Mac для этого проекта не требуется.

PhotoKit на iPhone может перечислять метаданные объектов, оригиналы которых отсутствуют на устройстве. Первый шаг — маленький компонент с одной кнопкой доступа и счётчиками на самом телефоне, без скачивания оригиналов и удаления. Требуется полный доступ: ограниченный доступ подтверждает только выбранную пользователем часть каталога. Нужно явно определить охват скрытых объектов, серий, Shared Albums и iTunes-снимков; числовое совпадение само по себе не доказывает полноту ресурсов. [PHAsset](https://developer.apple.com/documentation/photos/phasset), [fetchAssets](https://developer.apple.com/documentation/photos/phasset/fetchassets(with:)).

После подтверждения каталога iPhone должен передать метаданные и миниатюры по локальному соединению, чтобы пользователь выбирал на Mac. Затем телефон получает выбранные ресурсы через PhotoKit и передаёт их в независимый архив. Для оригинала, находящегося только в iCloud, нужен интернет на iPhone; запрет сети должен давать статус «недоступен локально», а не успешный импорт. Mac Photos не участвует. [PHAssetResourceManager](https://developer.apple.com/documentation/photos/phassetresourcemanager), [сетевой доступ ресурсов](https://developer.apple.com/documentation/photos/phassetresourcerequestoptions/isnetworkaccessallowed).

Через USB/ImageCaptureCore/AFC документированная гарантия полного PhotoKit-каталога, включая облачные записи, не установлена. Это не доказательство невозможности частных протоколов, но текущие 332 файла не подтверждают исходное требование. Стандартный браузерный file picker передаёт только файлы, выбранные пользователем на iPhone. [HTML File Upload](https://html.spec.whatwg.org/multipage/input.html#file-upload-state-(type=file)).

Для запуска компонента на собственном iPhone публикация в App Store не нужна: возможна установка через Xcode с Personal Team. Бесплатный профиль действует 7 дней, затем потребуется пересборка/переустановка; нужен Developer Mode. Установка ожидает выбора пользователя и не выполнена. [Apple Account](https://developer.apple.com/help/account/basics/about-your-developer-account), [Developer Mode](https://developer.apple.com/documentation/xcode/enabling-developer-mode-on-a-device).

Дополнительные USB-счётчики классифицируют отсутствующие SDK-объекты по UTI и сравнивают только уникальные ненулевые PTP handles. Последний контрольный CLI-запуск не обнаружил устройство; классификация двух дополнительных объектов дерева на реальном каталоге ещё не выполнена. Исходный готовый GUI-каталог и его числа от пользователя остаются основным свидетельством расхождения.
